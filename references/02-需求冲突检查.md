**原则**：动配置前先把题面拆成「硬性需求」，逐项映射技术，检查是否存在互斥或矛盾。
一旦发现冲突，**先停下来向用户说明并给 2–3 个可选方案，等拍板后再配**。

## 2.1 常见冲突类型

| 冲突 | 现象 | 解法 |
| --- | --- | --- |
| 标准 ACL 隔离 vs 主机互访 | “网段 A 不能访问网段 B” 与 “终端要互访” 互斥 | 改用**扩展 ACL**（可精细到目的），或**删除互访需求** |
| 公网网段掩码不一致 | 题面写 `x.x.x.x/24`，但只给 2 个地址实为 `/30` | 统一为 `/30`，NAT 池若不在直连段则对端加**回程路由** |
| NAT 地址池越界 | 池地址不在出口互联 `x.x.x.x/30` 段内 | 对端加 `ip route <池地址> 255.255.255.255 <对端互联地址>` 回程 |
| 生成树根桥冲突 | 两设备对同一 MST 实例都配最高优先级 | 明确主备（如 MST1 根 A、MST2 根 B），优先级错开 |
| VRRP 虚拟 IP 与 SVI 不一致 | `vrrp 10 ip` 不在该 VLAN 网段 | 虚拟 IP 必须与 SVI 同网段，通常取 `.254` |
| 地址重叠 / DHCP 范围撞保留 | excluded-address 没排除 SVI/网关 | 排除网关与 SVI（如 `.252-.254`）及需保留地址 |
| 全局 BPDU Guard 误伤上联 | `spanning-tree portfast bpduguard default` 把 trunk 也关了 | 改为**仅终端接口** `spanning-tree bpduguard enable` |

## 2.2 识别方法
1. 把每条需求列成表格：需求 → 用到的技术 → 作用对象 → 与其他需求的依赖。
2. 重点检查**过滤类（ACL）**与**连通类（路由/互访）**是否对立。
3. 检查所有网段掩码、网关、NAT 池是否自洽。
4. 检查可靠性（STP 根、VRRP 主备）是否唯一确定。

## 2.3 经典冲突示例（文字描述，无真实地址）
- **示例**：题面同时要求「终端 A 与终端 B 互访」+「用标准 ACL 拒绝网段 B 访问网段 A」。
  标准 ACL 只看源地址，在网关 SVI 出方向 `deny <网段B>` 会直接阻断双向互访。
- **决策**：删除「互访」要求（保留 ACL 隔离），或改为扩展 ACL 精确匹配目的地址。
- **教训**：标准 ACL 无法做到“单向允许互访、单向拒绝某网段”，这种需求要么改扩展 ACL，
  要么改需求。遇到先问用户走哪条路。
