# 01　连接与发现（阶段 0）

本环境是 **GNS3 + RG-NSE V1.06 模拟器**，每台设备通过 telnet 暴露一个本地端口。
终端是 **VPCS**（`PC1>` 提示符，无配置模式），交换机/路由器是 **锐捷 RGOS**。

## 1.1 主动询问 IP（不要硬编码）
每次开工先问用户：「当前模拟器所在主机的 IP 是多少？」
拿到后再做端口扫描，不要凭记忆写死。

## 1.2 端口扫描
用 `scripts/connect.py` 的 `scan` 子命令扫描一段端口，返回「端口 → 设备类型/banner」：

```bash
python connect.py scan --host <模拟器IP> --start 5000 --end 5020
```

把扫描结果（端口 → 设备类型）列出，请用户确认端口与设备的对应关系。

> 端口由 GNS3 按启动顺序动态分配，**不同工程、不同次启动都不一样，以本次扫描为准**，
> 禁止沿用任何历史端口映射。

## 1.3 设备类型识别（决定配置方式）
连上后看提示符与 `show version`：
- `PC1>` / `VPCS>` → **VPCS 终端**：无 `configure terminal`，直接敲 `ip dhcp`、`show ip`。
- `Switch>` / `Switch#` → **RGOS 交换机/路由器**：需 `enable` → `configure terminal`。
- `Router>` → 路由器（RGOS 命令集与交换机一致，差异在三层接口/路由）。

## 1.4 唤醒与进入特权模式
模拟器刚连上可能停在空 banner，先发回车唤醒；在用户模式先 `enable` 再读状态：

```bash
python connect.py shell --host <模拟器IP> --port <设备端口> --run "show version"
```

读取 `show version`（软件版本）、`show running-config`（当前配置）摘要，记录当前主机名，
便于阶段 3 判断是否要改名。

## 1.5 连接失败排查
- 端口连不上：确认模拟器已启动、对应设备已「开启远程连接端口」、IP/端口无误。
- 连上无回显：多发几次回车；检查是否需要先 `enable`。
- 大量乱码：终端协商问题，`connect.py` 已处理 IAC 与 ANSI 转义，正常无需干预。
